# Model Metrics and Methodology

## 1. Detailed Metric Audit

The prediction objective in this project is list-wise ordering, not binary event detection and not independent scalar regression. Every race instance is a closed ranking problem containing the same cohort size, and each driver's predicted finish must be interpreted in relation to the other thirteen veterans in the same field. Because of this, Information Retrieval (IR) metrics were selected as the governing measurement family. Global NDCG evaluates whether the model places the most relevant outcomes at the top while still crediting near-misses in lower ranks through logarithmic discounting, which is exactly the behavior needed when a model predicts second instead of first or fourth instead of third. NDCG@3 was added as a top-heavy operational metric to directly measure podium-list quality where strategic and communication value is highest. Mean Reciprocal Rank (MRR) was retained because it measures how quickly the true winner appears in the predicted ordering, making it a high-signal statistic for winner discovery quality in a ranker.

Traditional classification metrics were intentionally excluded because they treat outcomes as label identities rather than ordered positions with distance-sensitive penalties. Accuracy, precision, recall, and F1 only make sense after collapsing a ranking problem into class bins, which destroys list structure and removes ordinal proximity mechanics. In this domain, predicting P2 instead of P1 is far better than predicting P10 instead of P1, but classification-style metrics cannot represent that gradient without awkward reframing and information loss. Regression metrics such as MSE are similarly misaligned; while they penalize numeric distance, they evaluate each row independently and do not enforce the group-wise ordering constraints that define race ranking quality. The selected IR metrics therefore align with both the machine learning objective function and the real decision surface: quality of ordered lists inside race groups.

## 2. Train/Test Separation and Chronological Cross-Validation

The production split is now dynamic and season-relative. The system computes `max_season` from the processed matrix at runtime, trains on all seasons strictly earlier than `max_season`, and reserves `max_season` as the out-of-sample test season. This reproduces operational deployment conditions where a model is trained only on information available before the target season and then evaluated on future observations it has never seen. Random row-level train/test splitting is prohibited because it introduces look-ahead leakage: rows from future races can bleed into training while related rows from earlier races remain in validation, causing the model to absorb temporal signatures it would never possess in production. The consequence is inflated offline performance and a false sense of generalization.

To optimize hyperparameters without violating temporal integrity, the pipeline uses an expanding time-series cross-validation pattern over available historical seasons. Validation seasons are generated automatically from the train horizon and always progress chronologically, with the final validation fold anchored at `max_season - 1`. This expanding-window design emulates annual retraining practice and preserves causality because each validation fold is always in the future relative to its corresponding training window. In addition, race blocks are kept contiguous and unshuffled using `race_id` grouping so each race remains a coherent list-wise unit during training and evaluation. For ranking losses such as pairwise and lambdarank objectives, this is mathematically mandatory; breaking race blocks destroys the within-race comparator structure and can corrupt group boundaries, making both optimization and metric calculations invalid.

## 3. Hyperparameter Tuning Architecture

The hyperparameter tuning layer is implemented as an explicit deterministic grid search loop rather than ad hoc manual selection. For each model family, every candidate parameter tuple is fit and scored across all chronological folds, and the mean grouped NDCG across folds becomes the model-selection criterion. This approach gives a reproducible, auditable optimization path and ensures that parameter choices are justified by out-of-fold ranking quality instead of single-split luck.

For `XGBRanker`, the search space spans `max_depth` in {3, 5, 7}, `learning_rate` in {0.01, 0.05, 0.1}, and `reg_lambda` in {1, 10, 100}. These controls jointly regulate representational capacity, optimization pace, and L2 regularization strength. For `LGBMRanker`, the search space spans `num_leaves` in {7, 15, 31}, `learning_rate` in {0.01, 0.05, 0.1}, and `min_child_samples` in {5, 10, 20}. These parameters similarly shape tree expressiveness, boosting stability, and leaf-level sample support constraints. The best parameter tuple for each model is selected by maximizing mean grouped NDCG over the expanding folds, and the winning configuration is then refit on the full dynamic train horizon (all seasons < `max_season`) before final evaluation on `max_season`.

## 4. Strategic Data Leakage Prevention

Leakage prevention is treated as a first-class engineering requirement in this repository, especially during feature construction. In `build_veteran_features.py`, lagging with `.shift(1)` is used before rolling and cumulative feature calculations so that each feature value for race t is derived only from races < t. This design prevents the current target race from contaminating predictors that are supposed to be pre-race signals. Without lagging, rolling driver form, constructor points trajectories, and related temporal aggregates can inadvertently include the very race outcome being predicted, which creates target leakage hidden inside otherwise plausible features.

The failure mode without lagging is severe: the model learns mappings that partially encode the answer key, validation metrics appear artificially strong, hyperparameter search converges toward leakage-amplifying configurations, and production performance collapses when the leaked signal disappears in live inference. In practical governance terms, omitting lag operators converts the pipeline into a non-causal estimator. The current implementation avoids that failure by enforcing one-step temporal separation before any rolling computation, preserving strict feature causality and enabling trustworthy offline-to-online transfer.

## 5. Managing Fit Extremes (Overfitting vs. Underfitting)

The training pipeline is structured to balance two opposing risks: underfitting contemporary form and overfitting historical noise. Underfitting risk is reduced through exponential temporal sample weighting, where older seasons receive lower effective weight and recent seasons exert stronger influence during optimization. This allows the model to adapt to current performance regimes, regulation context, and competitive dynamics without discarding historical signal entirely. The weighting strategy acts as a controlled recency prior rather than a hard data cutoff, preserving statistical support while emphasizing modern relevance.

Overfitting risk is controlled through multiple orthogonal safeguards. First, strict chronological evaluation on the held-out latest season (`max_season`) prevents in-sample optimism from masquerading as real predictive quality. Second, conservative learning-rate candidates and explicit regularization controls (`reg_lambda`, leaf/sample bounds, and moderated tree depth/leaves) limit memorization pressure. Third, model selection is based on average grouped NDCG across multiple future-facing folds, which penalizes parameter sets that exploit idiosyncrasies in any single season. Together these controls produce a robust bias-variance compromise: enough capacity to learn meaningful race-order structure, but with sufficient regularization and temporal discipline to remain stable under distribution shift.
